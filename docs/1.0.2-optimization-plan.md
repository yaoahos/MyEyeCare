# MyEyeCare 1.0.2 优化方案

> 版本方向：1.0.2 ｜ 编制时间：2026-11-18
> 三个目标：① 按时间自动切换色温/亮度（日程曲线）；② 降低对比度（gamma 抬黑位 + 暖色温，文字不发灰）；③ 屏幕独立配置（主屏办公、副屏阅读分别配置）。
> 本方案基于当前 1.0.1 的实际代码结构编写，所有改动点均标注到具体文件/函数。文中“新增”“修改”指相对当前工作区源码。

---

## 一、现状与公共基础

### 1.1 当前生效链路

| 环节 | 位置 | 现状 |
|---|---|---|
| 配置结构 | `settings.rs` `Settings` | 单一结构，亮度/色温/遮罩/模板各一个字段，无“每屏”概念 |
| gamma 算法 | `gamma.rs` `build_ramp(brightness, kelvin)` | `value = (i/255)^(1/brightness)` × `channel_gains(kelvin)`；纯幂曲线，无黑位/对比度参数 |
| 推送屏幕 | `gamma.rs` `push_ramp(ramp)` | 枚举所有 `DISPLAY_DEVICE_ACTIVE`，对每个物理 DC 推**同一份** ramp |
| 遮罩 | `overlay.rs` | 单个分层窗口，几何取虚拟桌面 `GetSystemMetrics(SM_XVIRTUALSCREEN…)`，一种颜色一个透明度 |
| 状态快照 | `settings.rs` `CURRENT` | 进程内快照，供 `display.rs` 息屏恢复时原样重应用 |
| 显示监听 | `display.rs` | 电源通知 + 分辨率/DPI 变化 + 6 秒兜底定时，`reapply()` 读快照重应用 |
| 前端 | `app.js` `applyNow()` / `scheduleSave()` | 整包 `state` 发给 `apply_effect` / `save_settings`；模板点击 = 覆盖一组值 |

### 1.2 前置重构（三个方向共享，建议先做）

三个方向都会碰到“生效配置”这个概念，先统一抽象，避免各做各的：

- 引入 **EffectiveSettings** 概念：最终写进 gamma/遮罩的那组值，来源是「手动值」或「日程计算值」。
- `display.rs::reapply()` 不再直接读 `CURRENT` 原样重应用，而是先向调度/配置层取“此刻应有的 EffectiveSettings”再应用——这样息屏唤醒、定时兜底都能自动跟随日程曲线。
- `Settings` 采用 `#[serde(default)]` 已有平滑升级能力，新增字段全部给默认值，老用户 `settings.json` 无需迁移脚本。

> 工作量：M。此步是方向一、三的依赖，不单独产生用户可见功能。

## 二、方向一：按时间自动切换色温/亮度（昼夜两态）

> **设计变更（参考高星项目）**：初版方案是「多控制点曲线 + 用户拖拽」，实测中用户反馈"圆点方点数值对不上、曲线看不懂"。参考 GitHub 高星同类项目 **Tyrrrz/LightBulb（~2.8k star）** 与 **jonls/redshift（~6k star）** 后，改为它们验证过的**昼夜两态模型**：
> - 用户只设「白天」「夜晚」两组色温+亮度，加日出/日落时刻与过渡时长；
> - 曲线是**按公式算出来的只读展示**，不是可拖拽的编辑控件——参数即数值，从根上消除"点线数值脱节"；
> - 过渡用余弦 `sin/cos` 而非线性折线，两端斜率为 0、无折角跳变（LightBulb `Cycle.cs` 做法）。
> LightBulb 默认值：白天 6600K/100%、夜晚 3900K/85%、过渡 40 分钟；本项目沿用。

### 2.1 目标

用户设白天/夜晚两组目标色温与亮度、日出/日落时刻、过渡时长；应用在日出/日落附近平滑过渡。典型场景：白天冷白高亮、夜晚暖黄低亮。

### 2.2 数据结构（`settings.rs`）

```rust
// Settings 新增（昼夜两态）：
pub day_temperature: u32,      // 默认 6600
pub day_brightness: f64,       // 默认 1.0
pub night_temperature: u32,    // 默认 3900
pub night_brightness: f64,     // 默认 0.85
pub sunrise_minute: u16,       // 默认 07:20
pub sunset_minute: u16,        // 默认 18:30
pub transition_minutes: u16,   // 默认 40，以日出/日落为中心前后各半
pub schedule_enabled: bool,
pub manual_override_until: i64,
// 旧字段 schedule_points / SchedulePoint 保留仅为兼容历史配置，不再使用
```

### 2.3 调度实现（`schedule.rs`）

- `interpolate(s, minute) -> (temp, bright)`：以日出/日落为中心，前后 `transition/2` 分钟为过渡窗口，用 `(1±cos(π·p))/2` 平滑；窗口外用"距日出正向偏移 < 白昼长度"判断白天/夜晚（支持跨午夜）。
- 定时线程 `mec-schedule`：每 30 秒 tick，差异超阈值（温度 ≥ 30K 或亮度 ≥ 0.01）才写 gamma，避免闪烁。
- 阈值缓存 `LAST_APPLIED`：手动覆盖到期时清空，保证交还后第一次写入不被阈值拦截。
- 命令：`set_schedule_config`（写回昼夜参数）、`set_schedule_enabled`、`set_manual_override`、`get_effective_settings`、`get_schedule_curve`。
- 前端用**与 Rust 完全同源**的 JS 公式本地绘制曲线，保证"显示的此刻值 = 真正生效值"。

### 2.4 与手动调节/模板的优先级（关键规则）

- **自动优先为默认**：`schedule_enabled` 且未覆盖时，滑杆显示日程计算值。
- **手动临时覆盖**：用户调滑杆/点模板 → `manual_override_until = now + 30min`，界面显示倒计时与[恢复自动]；到期自动接管。
- 总开关 `enabled` 关闭时，调度与覆盖全部暂停，恢复原始屏幕。

### 2.5 前端日程 UI

- 卡片左右两栏：左侧「白天 / 夜晚」两组数字输入（色温 K、亮度 %）+ 日出/日落时间 + 过渡分钟；右侧只读 SVG 曲线（橙=色温、绿=亮度），日出/日落竖线区分色，当前时刻指针随调度移动。
- 信息行显示：`白天 6600K·100% ｜ 夜晚 3900K·85% ｜ 当前 白天/夜晚/过渡中`，以及"此刻 xxxK · xx%"。
- 曲线随参数输入实时重绘；窗口 760×710、无滚动条，底部卡片完整可见。

### 2.6 风险与验收

| 风险 | 应对 |
|---|---|
| 频繁写 gamma 导致闪烁/耗电 | 差异阈值 + 30 秒 tick，非必要不写 |
| 休眠后时间跳变 | 复用唤醒钩子强制重算 |
| 手动与自动状态打架 | 覆盖状态持久化 + 明确的到期恢复 |
| 前后端曲线不一致 | 两端用同源余弦公式，参数同源 |
| 旧配置缺字段 | serde default + 0 值兜底迁移到新默认值 |

验收：昼夜参数改动后曲线与生效值一致；日出/日落处平滑过渡无跳变；手动覆盖到期自动恢复；息屏唤醒后跟随当前时段；关闭总开关后不写 gamma。

工作量：M（调度 M + 只读曲线 UI S，比多控制点拖拽方案显著简化）。

## 三、方向二：降低对比度（抬黑位 + 暖色温，文字不发灰）

### 3.1 关键约束：为什么“抬黑位”和“文字不发灰”天然冲突

降低对比度的本质是压缩动态范围：抬高黑位（黑→深灰）+ 压低白位（白→浅灰）。但黑色文字正落在被抬升的黑位上——抬得越多，文字越灰、越不锐利。所以**必须把抬升幅度限制在人眼几乎不可察觉的范围内**，并把对比度下降主要放在中间调，而不是简单把整条曲线平移。

### 3.2 曲线设计（修改 `gamma.rs::build_ramp`）

当前为 `base = (i/255)^(1/brightness)`。增加两级处理，用一个“柔和度”旋钮 `softness ∈ [0,100]` 统一控制：

1. **抬黑位**：`lift = 0.03 * softness/100`（上限 0.03，即黑位最高抬到约 8/255）。
   `v = lift + (1 - lift) * base`
   —— 纯黑只到近黑（≤8/255），文字仍呈黑色，不发灰。
2. **中段压缩**：`v = v^(1 + 0.35 * softness/100)`，让中间调斜率略降、对比度降低，而黑端（≈lift）和白端（≈1）基本不动，锐度保留。
3. **暖色温**：沿用现有 `channel_gains(kelvin)` 相乘，不新增算法；本方向默认搭配偏暖色温（如 5200K）即可获得“暖 + 柔”观感。

默认 `softness = 25`（lift≈0.0075，极轻微），用户可自行加大。说明：不建议把 lift 暴露成独立参数——超过 0.05 文字会明显发灰，单旋钮更安全。

### 3.3 与现有参数的关系

- 亮度仍是幂曲线，对比度处理在其之后，两者正交，可叠加。
- 方向一的日程插值对 `softness` 同样插值（或日程只管色温/亮度，softness 全局固定——建议后者，减少复杂度）。
- 遮罩层也能降对比度，但会给文字蒙色；gamma 层不改色相、文字更干净，因此选 gamma 层实现，“遮罩”继续只负责氛围色。

### 3.4 前端与验收

- 设置/调节区加一个“柔和度”滑杆（与曲线卡片同行排布，缓解 2.5 的空间压力），实时 A/B 预览按钮“对比效果”。
- 验收用标准测试图：白底黑字 + 黑底白字 + 21 级灰阶；量化黑字区域最小亮度提升 ≤ 10/255、灰阶单调无并阶。
- **需真机实测确认文字锐度**——此项无法在当前环境自动验证，作为发布前的手动卡点。

工作量：S（算法）+ M（UI/验证）。

### 3.5 风险

| 风险 | 应对 |
|---|---|
| 驱动对 ramp 低端量化粗糙 | lift 上限压到 0.03；实测低端无并阶 |
| 低亮度叠加 lift 使暗部发糊 | 亮度越低，按比例减小 lift |
| 文字发灰主观性强 | 提供 A/B 对比 + 默认值极轻微 |

## 四、方向三：屏幕独立配置

### 4.1 目标

“主屏办公、副屏阅读”各自拥有亮度/色温/遮罩（含方向二的柔和度），互不影响。这是三个方向中改动最大的一块，涉及 gamma 推送、遮罩窗口、设备标识、前端交互四处。

### 4.2 数据结构（`settings.rs`）

```rust
pub struct DisplayProfile {
    pub key: String,            // 稳定设备标识，见 4.3
    pub label: String,          // 展示名，如“主屏 · 2560×1440”
    pub brightness: f64,
    pub temperature: u32,
    pub softness: u32,          // 方向二参数
    pub overlay_enabled: bool,
    pub overlay_color: String,
    pub overlay_strength: u32,
}
// Settings 新增：
pub display_mode: enum { Unified, Independent },   // 统一 / 分别配置
pub per_display: Vec<DisplayProfile>,
```

`Unified` 模式沿用现有顶层字段；`Independent` 模式读 `per_display`。默认 `Unified`，老用户零感知。

### 4.3 设备标识（稳定性关键）

- `device_name`（`\\.\DISPLAY1`）在热插拔/重启后编号会变，不能作为 key。
- 用 `DISPLAY_DEVICEW.device_id`（含硬件信息）做稳定 key（可做短哈希存字符串）；`device_string` 作展示名；主屏由 `state_flags & DISPLAY_DEVICE_PRIMARY_DEVICE` 判定。
- 提供命令 `list_displays() -> Vec<DisplayInfo>`（key、名称、是否主屏、分辨率、虚拟桌面坐标），供前端渲染屏幕选择。
- 热插拔后按 key 匹配配置；匹配不到时用“位置 + 序号”兜底并提示用户重新配置。

### 4.4 gamma 按屏拆分（`gamma.rs`）

- `push_ramp(ramp)` 改为 `push_ramp_per_display()`：一次枚举中同时拿到 device_name 与 device_id，按 key 查 `per_display`，为每屏单独 `build_ramp(brightness, temperature, softness)` 后 `SetDeviceGammaRamp` 到该屏 DC。
- 保留“全部屏推 identity”的 `reset()` 语义；`gamma_probe()` 扩展到可读多屏。

### 4.5 遮罩按屏拆分（`overlay.rs`，工作量最重）

- 由单窗口改为“每屏一个分层窗口”：用 `EnumDisplayMonitors` 取每屏 `rcMonitor` 与 `szDevice`，维护 `HashMap<key, HWND>`。
- `apply()` 按 profile 更新各自颜色/透明度；无遮罩的屏隐藏其窗口。
- `refresh()` 重新枚举监视器同步几何；退出时销毁全部窗口。
- 成本：多屏多几个分层窗口，内存仍是 MB 级；每屏纹理独立，无额外 WebView/进程。

### 4.6 前端与联动

- 调节页顶部加一排屏幕 chip（“主屏”“副屏”+ 分辨率），点击切换 `activeDisplayId`，其后所有滑杆/模板/遮罩操作作用于该屏。
- “统一配置 / 分别配置”切换；切换时把当前值复制到各屏作为初始值。
- 模板匹配 `matchTemplate()` 按当前屏配置计算，避免主屏模板被副屏误判。

### 4.7 与方向一的组合边界（明确 scope）

日程曲线与屏幕独立配置叠加会导致“每屏一条曲线”的状态爆炸。**建议 1.0.2 内两者互斥**：

- `Independent` 模式下日程自动暂停（界面提示“分别配置模式下日程暂不生效”）；
- `Unified` 模式下日程正常作用。

这样既覆盖“主屏办公、副屏阅读”的静态差异，又不引入组合复杂度。若后续需要“每屏各自日程”，列为 1.0.3+ 议题。

### 4.8 风险与验收

| 风险 | 应对 |
|---|---|
| 设备 key 漂移 | 用 device_id 稳定标识 + 匹配失败兜底 |
| 遮罩多窗口层级/几何错乱 | 复用现有 WM_MEC_REFRESH 机制扩展 |
| 热插拔后配置丢失 | WM_DISPLAYCHANGE 重建窗口并重应用 |
| 主屏副屏识别错误 | 用 PRIMARY_DEVICE 标志，前端可手动标注 |

验收：两屏设不同值互不串扰；拔插副屏再接回保持配置；息屏唤醒两屏各自恢复；统一/分别模式切换值迁移正确。

工作量：L（gamma M + overlay L + UI M + 联调 M）。

## 五、依赖关系与落地顺序

```
前置重构(settings/EffectiveSettings/reapply)
        │
        ├── 方向二 对比度算法（改 build_ramp，参数进 Settings）
        │            │
        │            └── 参数进入 DisplayProfile
        │
        └── 方向三 屏幕独立配置（数据结构 → gamma 拆分 → overlay 拆分 → UI）
                     │
                     └── 提供“按屏生效”能力
                                  │
                     方向一 日程曲线（输出 EffectiveSettings，按当前模式作用到屏）
```

推荐分期落地（均属 1.0.2 方向，内部按风险拆批）：

| 批次 | 内容 | 理由 |
|---|---|---|
| A | 前置重构 + 方向二 | 改动集中、可快速真机验证文字锐度，风险最低 |
| B | 方向一 | 新增模块，与现有架构兼容，独立可测 |
| C | 方向三 | 改动面最大（尤其 overlay 多窗口），单独打包验证 |

> 说明：若时间/验证资源有限，建议至少完成 A+B；方向三可作为 1.0.2 的后续批次或 1.0.3，避免一次引入过多变量。

## 六、体积与性能影响

- 三个方向主要使用现有 Win32 调用与已有依赖，**不新增第三方库**，体积增量预计 < 50 KB。
- 日程曲线用纯 SVG/前端绘制，不加图表库。
- 定时开销：日程 30 秒 tick + 现有显示监听 6 秒兜底，均为低频，CPU 影响可忽略。
- 注意：上一轮“软件内下载更新”引入 reqwest + tokio，体积 2.71 MB → 3.23 MB（+538 KB），属独立于本方案的既有变更，不计入 1.0.2 三个方向的增量。

## 七、需要拍板的取舍（含建议）

1. **范围**：建议按 A→B→C 分期，C（屏幕独立配置）可延后。若你要求三个一次性全做完，则按第五节顺序一次性提交验证。
2. **日程与分屏组合**：建议 1.0.2 内互斥（见 4.7）。这是避免状态爆炸的关键取舍。
3. **手动覆盖时长**：建议 30 分钟并可一键恢复自动；若你希望“手动即永久、直到重启”也可调整。
4. **柔和度默认值**：建议 25（极轻微）；可先按此发布，收集反馈后再调默认。
5. **UI 空间**：曲线卡片与柔和度滑杆会挤压固定的 680×550 面板，建议替换或合并设置页中较低价值的一块（候选：把“柔色遮罩颜色”六色卡折叠为一行小色点）。这一项需你确认可接受后再动布局。
